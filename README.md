# Table Importer

Библиотека на Python для анализа метаданных и импорта табличных данных из CSV, XLSX и SQLite с единым интерфейсом.

Проект поддерживает предварительное сканирование таблиц, чтение данных чанками, управление сессией импорта, преобразование типов данных, отслеживание прогресса и расширение списка поддерживаемых источников.

## Возможности

- **Единый интерфейс:** работа с CSV, XLSX и SQLite через `TableImporter`.
- **Сканирование данных:** получение метаданных листа или таблицы, включая число строк, если его удалось определить в пределах сканирования, и информацию о столбцах.
- **Чтение чанками:** последовательное чтение данных частями заданного размера.
- **Сессии импорта:** возможность приостанавливать и возобновлять чтение в рамках текущей сессии.
- **Преобразование типов:** приведение столбцов к указанным типам данных.
- **Отслеживание прогресса:** callback-функция получает количество уже обработанных строк.
- **Обработка ошибок:** специализированные исключения для различных ситуаций.
- **Расширяемость:** возможность добавлять собственные источники данных через реестр.
- **Тестирование производительности:** генерация больших наборов данных и измерение времени импорта.

## Поддерживаемые источники

| Формат | Расширения | Источник |
|---|---|---|
| CSV | `.csv` | `CsvSource` |
| Excel | `.xlsx` | `ExcelSource` |
| SQLite | `.db`, `.sqlite`, `.sqlite3` | `SQLiteSource` |

## Требования

- Python 3.11 или новее.
- `pandas` для работы с табличными данными.
- `openpyxl` для работы с файлами XLSX.

Для разработки и запуска тестов используется `pytest`, для проверки стиля кода — `ruff`.

## Быстрый старт

### Сканирование таблицы

```python
from table_importer import TableImporter

importer = TableImporter()

metadata = importer.scan("data/example.csv")

print("Имя:", metadata.name)
print("Строк:", metadata.row_count)
print("Столбцов:", metadata.column_count)

for column in metadata.columns:
    print(column)
```

Метод `scan()` возвращает метаданные таблицы, а не сам DataFrame. Параметр `sample_size` позволяет задавать размер выборки для анализа данных:

```python
metadata = importer.scan(
    "data/example.csv",
    sample_size=1000,
)
```

`metadata.scanned_rows` показывает, сколько строк было просмотрено. `metadata.row_count` содержит точное число строк, только если источник целиком поместился в выборку; для более крупных источников значение равно `None`, а `metadata.row_count_is_exact` равно `False`. Библиотека не делает дополнительный полный проход по источнику ради подсчёта строк.

Типы столбцов и количество пропусков рассчитываются по просмотренным строкам. Поле `metadata.missing_counts_are_exact` показывает, охватывает ли этот подсчёт весь источник.

### Импорт данных

```python
from table_importer import TableImporter

importer = TableImporter()

df = importer.import_data(
    "data/example.csv",
    chunk_size=10_000,
)

print(df.head())
print(df.shape)
```

Метод `import_data()` выполняет импорт и возвращает итоговый `pandas.DataFrame`.

Для Excel можно указать имя листа, а для SQLite — имя таблицы, если оно поддерживается источником как имя листа:

```python
df = importer.import_data(
    "data/example.xlsx",
    sheet_name="Sheet1",
    chunk_size=10_000,
)
```

Если имя листа не задано, библиотека выбирает первый доступный лист или таблицу согласно реализации источника. Для CSV имя листа обычно указывать не требуется.

### Управление сессией импорта

Если необходимо управлять чтением по шагам, можно создать сессию:

```python
from table_importer import TableImporter

importer = TableImporter()

session = importer.create_session(
    "data/example.csv",
    chunk_size=1000,
)

while not session.is_finished:
    chunk = session.read_next_chunk()
    print(f"Получено строк: {len(chunk)}")

df = session.get_result()
```

Сессию можно приостановить и затем продолжить:

```python
session.pause()

# Пока сессия приостановлена, чтение следующего чанка недоступно.

session.resume()
```

Сессия хранит своё состояние в памяти текущего процесса. Сохранение состояния на диск и восстановление сессии после перезапуска программы не реализованы.

### Преобразование типов и отслеживание прогресса

```python
from table_importer import TableImporter

def show_progress(rows_processed: int) -> None:
    print(f"Обработано строк: {rows_processed}")

importer = TableImporter()

df = importer.import_data(
    "data/example.csv",
    chunk_size=5000,
    dtype={
        "id": "int64",
        "value": "float64",
    },
    progress_callback=show_progress,
)
```

Словарь `dtype` задаёт типы столбцов, которые нужно преобразовать. Если преобразование невозможно, библиотека может выбросить специализированное исключение.

Callback получает количество строк, обработанных к моменту вызова, а не процент выполнения.

## Тестирование

Функциональные тесты проверяют поведение источников данных, сканирование, импорт, обработку ошибок, преобразование типов, сессии и другие основные сценарии.

Запуск тестов:

```bash
python -m pytest
```

Проверка стиля кода:

```bash
ruff check .
```

Тесты на небольших файлах предназначены для проверки конкретных сценариев и граничных случаев. Большие синтетические наборы используются отдельно для экспериментальной оценки производительности.

## Генерация больших наборов данных

Для экспериментов можно создать синтетические файлы CSV, XLSX и SQLite.

Например, сгенерировать по 100 000 строк:

```bash
python scripts/generate_test_data.py --rows 100000
```

Создать наборы по 500 000 строк:

```bash
python scripts/generate_test_data.py --rows 500000
```

Генератор поддерживает выбор форматов:

```bash
python scripts/generate_test_data.py --rows 500000 --formats csv sqlite
```

По умолчанию файлы сохраняются в каталоге `data/generated/`. Этот каталог предназначен для локальных экспериментов; сгенерированные файлы не требуется добавлять в репозиторий.

## Измерение производительности

После генерации данных можно выполнить бенчмарк:

```bash
python scripts/benchmark_import.py --rows 100000
```

Для набора из 500 000 строк:

```bash
python scripts/benchmark_import.py --rows 500000
```

Можно выбрать форматы и изменить размер чанка:

```bash
python scripts/benchmark_import.py \
    --rows 500000 \
    --chunk-size 10000 \
    --formats csv sqlite
```

Бенчмарк измеряет время полного импорта, количество строк и пиковую память, отслеживаемую `tracemalloc`.

### Результаты эксперимента

Эксперименты на наборах из 100 000 и 500 000 строк показали следующие результаты:

| Формат | 100 000 строк | 500 000 строк |
|---|---:|---:|
| CSV | 0,23 с | 1,00 с |
| XLSX | 82,83 с | 433,17 с |
| SQLite | 0,78 с | 3,77 с |

Во всех экспериментах импортировано ожидаемое количество строк.

CSV оказался самым быстрым форматом в проведённых измерениях, а XLSX — самым медленным. Значения зависят от оборудования, окружения и используемых библиотек; подробные результаты, включая отслеживаемую память и ограничения измерений, приведены в [`specs/performance.md`](specs/performance.md).

**Важно:** чтение чанками не означает, что итоговое потребление памяти ограничено размером чанка. В текущей реализации сессия сохраняет прочитанные части в памяти и затем объединяет их в итоговый DataFrame.

## Ограничения

- Импорт большого файла с последующим созданием единого DataFrame может требовать значительного объёма памяти.
- Приостановка и возобновление сессии работают только в рамках текущего процесса.
- Для источников, превышающих `sample_size`, `row_count` неизвестен (`None`), поскольку библиотека не читает источник целиком только ради подсчёта строк.
- Типы столбцов и число пропусков описывают просканированную выборку и могут не отражать свойства всех строк.
- Производительность XLSX существенно ниже производительности CSV и SQLite в проведённых экспериментах.
- Измерения бенчмарка не являются полноценным профилированием памяти процесса.
