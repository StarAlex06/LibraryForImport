# Стратегия тестирования

## 1. Цели тестирования

Тестирование `table-importer` направлено на проверку двух аспектов:

1. **Функциональная корректность:** библиотека возвращает ожидаемые данные, правильно обрабатывает метаданные, типы, пропуски и ошибки.
2. **Поведение на больших источниках:** библиотека способна обрабатывать увеличивающиеся объёмы данных в пределах доступных ресурсов.

Эти аспекты проверяются разными наборами сценариев.

## 2. Автоматические функциональные тесты

Для автоматических тестов используются небольшие контролируемые файлы, создаваемые непосредственно в тестах.

Это позволяет:
- точно задавать исходные данные и ожидаемый результат;
- воспроизводить ошибки;
- проверять граничные случаи;
- быстро запускать тесты при изменении кода;
- не зависеть от доступности внешних датасетов.

Основные сценарии включают проверку поддерживаемых форматов, метаданных, пропущенных значений, преобразования типов, импорта порциями, управления состоянием сессии и обработки ошибок.

Точный набор сценариев определяется фактическим покрытием тестами проекта.

## 3. Генерация больших данных

Для воспроизводимых экспериментов предусмотрен отдельный скрипт генерации тестовых источников. Он позволяет создавать файлы заданного размера без зависимости от внешних наборов данных.

Генерируемые данные предназначены для технической проверки поведения библиотеки, а не для моделирования конкретной предметной области.

## 4. Проверка больших источников

Нагрузочные эксперименты следует выполнять отдельно от обычного набора тестов, поскольку они могут занимать заметное время и потреблять значительные ресурсы.

Для каждого эксперимента рекомендуется фиксировать:

- формат и количество строк;
- размер порции импорта;
- время выполнения;
- успешность завершения;
- количество фактически обработанных строк;
- используемую среду выполнения.

Если измеряется потребление памяти, необходимо указать способ измерения и его ограничения. В частности, `tracemalloc` отслеживает выделения памяти Python, но не отражает полностью все выделения нативной памяти библиотеками вроде NumPy.

## 5. Воспроизводимость

Генерация данных и запуск экспериментов должны выполняться командами, приведёнными в README.

Обычные тесты не должны зависеть от предварительного создания больших файлов. Это сохраняет возможность быстро проверять корректность библиотеки на разных компьютерах.

## 6. Интерпретация результатов

Результаты одного запуска не следует считать универсальной оценкой производительности: время зависит от оборудования, версии Python, библиотек, формата источника и доступной памяти.

Выводы о производительности должны опираться на фактически проведённые эксперименты. Если эксперимент ещё не выполнялся, результаты и численные показатели не указываются.
