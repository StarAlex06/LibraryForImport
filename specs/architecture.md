# Архитектурные решения

## 1. Цель проекта

`table-importer` — библиотека для сканирования и импорта табличных данных из CSV-файлов, Excel-книг и баз данных SQLite.

При проектировании учитывались следующие требования:

- единый интерфейс для разных источников данных;
- получение метаданных без обязательного полного импорта данных;
- возможность обрабатывать данные порциями;
- управление состоянием импорта;
- контроль ошибок и преобразования типов;
- возможность расширять набор поддерживаемых источников.

## 2. Единый интерфейс для источников данных

Для CSV, Excel и SQLite используются разные механизмы чтения, однако с точки зрения пользователя задачи во многом одинаковы: определить структуру источника, получить метаданные и импортировать данные.

Поэтому работа с источниками организована через общий интерфейс. Это позволяет отделить логику управления импортом от деталей конкретного формата.

**Преимущества:**
- меньше дублирования общей логики;
- единообразное использование библиотеки;
- возможность добавлять новые источники, не переписывая весь код.

**Компромисс:** разные форматы имеют собственные особенности. Общий интерфейс должен учитывать их, не скрывая существенные ограничения конкретного источника.

## 3. Разделение сканирования и импорта

Получение метаданных и импорт содержимого решают разные задачи.

Сканирование позволяет узнать структуру источника, предполагаемые типы столбцов и информацию о пропущенных значениях. Размер выборки задаётся параметром `sample_size`. Поля `scanned_rows`, `row_count_is_exact` и `missing_counts_are_exact` позволяют интерпретировать результат.

Если в выборку поместились все строки источника, `row_count` содержит точное число строк, а сведения о пропусках относятся ко всему источнику. Если источник больше выборки, `row_count` равен `None`; библиотека не выполняет отдельный полный проход ради точного подсчёта. Типы и пропуски в этом случае рассчитываются только по выборке.

Импорт предназначен для получения самих данных. Разделение операций позволяет предварительно изучить источник, не выполняя полный импорт только ради получения информации о его структуре.

При использовании выборки необходимо учитывать, что некоторые метаданные относятся только к просмотренным строкам. Точный размер больших источников не сообщается, чтобы сканирование не превращалось в полный проход по данным.

## 4. Чтение данных порциями

Для управления импортом предусмотрена обработка данных блоками настраиваемого размера.

Такой подход позволяет ограничивать объём данных, обрабатываемых за один шаг, и удобен для источников, которые нецелесообразно читать целиком одной операцией.

При этом чтение порциями само по себе не гарантирует постоянного потребления памяти: итоговая сборка всех прочитанных блоков в один `DataFrame` может потребовать значительного объёма памяти. Поэтому этот механизм следует рассматривать как способ управления процессом чтения, а не как гарантию потоковой обработки с ограниченным потреблением памяти.

## 5. Сессии импорта

Сессия импорта инкапсулирует состояние процесса и предоставляет операции для последовательного чтения блоков, приостановки и возобновления работы.

Это отделяет управление состоянием импорта от кода, который использует библиотеку.

Важно различать приостановку сессии в рамках её текущего жизненного цикла и сохранение состояния на диск для восстановления после перезапуска программы. Наличие второго механизма не предполагается без отдельной реализации.

## 6. Преобразование типов и обработка ошибок

Для задания типов столбцов используется интерфейс, совместимый с механизмами `pandas`. Это позволяет использовать привычные обозначения типов и интегрироваться с экосистемой Python для анализа данных.

Для ошибок предусмотрена иерархия собственных исключений. Она позволяет различать проблемы с источником, форматом, сканированием, импортом, преобразованием типов и состоянием сессии.

Такой подход делает ошибки понятнее вызывающему коду и позволяет обрабатывать разные категории проблем отдельно.

## 7. Расширяемость

В библиотеке предусмотрен механизм регистрации источников данных. Он позволяет расширять набор форматов, сохраняя общий подход к работе с ними.

При добавлении нового источника необходимо реализовать предусмотренный библиотекой интерфейс и проверить его поведение на общих сценариях и специфических случаях соответствующего формата.

## 8. Основные компромиссы

При проектировании учитывались следующие компромиссы:

- **Единый интерфейс против особенностей форматов.** Унификация упрощает использование, но не отменяет различий между CSV, Excel и SQLite.
- **Сканирование выборки против полноты метаданных.** Выборка ограничивает объём чтения, но для источников больше выборки точное число строк неизвестно, а типы и пропуски характеризуют только просмотренные данные.
- **Чтение порциями против итоговой сборки результата.** Порционное чтение даёт контроль над обработкой, но объединение блоков в итоговый `DataFrame` всё ещё может потребовать значительной памяти.
- **Абстракция против сложности реализации.** Общие интерфейсы облегчают расширение, но требуют дополнительных компонентов и тестов.

## 9. Почему выбраны эти технологии и настройки

### Библиотеки

- **pandas** используется потому, что итоговый результат по условию — `DataFrame`. Он также предоставляет чтение CSV, преобразование типов, объединение блоков и интеграцию с Excel- и SQLite-источниками. Это уменьшает объём собственного кода преобразования данных.
- **openpyxl** выбран как движок для XLSX. `pandas.read_excel()` используется для чтения заголовков и ограниченной выборки, а для импорта блоками применяется итератор openpyxl в режиме `read_only`, чтобы не загружать лист целиком в память.
- **sqlite3** взят из стандартной библиотеки Python: SQLite поддерживается без дополнительной зависимости. Результаты запросов переводятся в `DataFrame` средствами pandas.
- **pytest** и **ruff** находятся в необязательной группе `dev`: они нужны для разработки, но не для установки и использования библиотеки.

### Интерфейс и чтение

- **`DataSource` и `SourceRegistry`** отделяют API импорта от формата. Реестр по расширению файла выбран как простой способ подключить дополнительные файловые источники без системы entry points или внешней инфраструктуры плагинов. Поэтому текущая регистрация рассчитана на источники, которые можно открыть по пути и определить по расширению.
- **`iter_chunks()`** позволяет источнику переопределить способ последовательного чтения, сохранив общий интерфейс с `read_chunk()`. CSV использует постоянный pandas reader, XLSX — итератор openpyxl в режиме `read_only`. Для SQLite применяется `LIMIT/OFFSET`: это позволяет запрашивать очередной блок по смещению без сохранения курсора БД между вызовами. Цена простоты — чтение дальних блоков может замедляться, поскольку базе приходится пропускать предыдущие строки. SQL-запрос не задаёт `ORDER BY`, поэтому библиотека не обещает определённый порядок строк SQLite.
- **Выбор первого листа или таблицы по умолчанию** упрощает вызов для источников с одним набором данных. Для многолистовых книг и баз можно передать `sheet_name` явно. Порядок по умолчанию задаёт сам источник: порядок листов книги, имя CSV-файла или алфавитный порядок таблиц SQLite.
- **Сессия хранит прочитанные блоки в памяти**, потому что публичный контракт требует вернуть один итоговый `DataFrame`. Это упрощает API и сборку результата, но не ограничивает общую память размером чанка. Запись в файл или передача блоков потребителю потребовала бы другого API.

### Значения по умолчанию

- **`sample_size=1000`** даёт ограниченную выборку для предварительной оценки типов и пропусков, не требуя полного чтения большого источника. Значение выбрано как практический стартовый размер, а не как универсальный или экспериментально оптимальный; вызывающий код может его изменить.
- **Чтение `sample_size + 1` строк** позволяет определить, помещается ли весь источник в выборку. Если дополнительная строка есть, библиотека знает, что источник больше выборки, и не утверждает точный `row_count`.
- **`chunk_size=10_000`** выбран как удобное значение по умолчанию для итерационного импорта и используется в бенчмарке проекта. Сравнительного измерения разных размеров чанка нет, поэтому это значение не заявляется как оптимальное для всех форматов и нагрузок.
- **Python 3.11+** указан как минимальная версия проекта и среда, под которую подготовлены настройки пакета. Код не опирается на уникальную возможность Python 3.11; более низкую границу можно было бы задать после проверки зависимостей и тестов на этой версии.

### Ошибки

Собственные классы исключений сгруппированы по действиям, которые выполняет библиотека: поиск источника, выбор листа или таблицы, сканирование, импорт, преобразование типов и состояние сессии. Это позволяет вызывающему коду обрабатывать категории ошибок отдельно. Исходное исключение сохраняется в цепочке (`raise ... from exc`), чтобы не терять техническую причину.

## 10. Проверка решений

Корректность реализации проверяется автоматическими тестами на контролируемых данных. Отдельные эксперименты с большими источниками позволяют оценить поведение библиотеки при увеличении объёма входных данных.

Описание тестового подхода и воспроизведения экспериментов приведено в `testing_strategy.md`.
